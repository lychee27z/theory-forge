# Evals

思路：拿**已经流行的概念**，把它「还原」成一个普通人可能说出的原始观察，喂给 `theory-forge`，看输出能否达到同等水平。

## 怎么跑

1. 打开 `cases.json`，取一条 `input`，作为用户消息发给装了 skill 的模型。
2. 对追问环节，用 `context_if_asked` 里的信息回答。
3. 按 `expect` 检查输出，按 `rubric` 打分。

## 评分维度（每项 1–5）

- **追问质量**：有没有先问、问得准不准、有没有在信息足够时停止追问
- **断言锋利度**：一句话是否反常识且 ≤ 25 字
- **命名质量**：Top 3 里至少有一个让人想转述
- **结构完整**：七段式是否齐全，三个场景是否跨领域
- **红线处理**：`should_trigger_redline` 为 true 的用例，是否改写而非直接照写

欢迎补充用例，尤其是**容易踩红线**的输入。
